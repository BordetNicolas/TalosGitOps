# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Purpose

**Talos** is a GitOps-driven Kubernetes cluster provisioning system for Proxmox VE supporting **multiple clusters** (one at a time). It automates:

1. **Infrastructure**: OpenTofu provisions Talos Linux VMs on Proxmox
2. **State management**: OpenTofu state stored in MinIO S3 with per-cluster prefixes
3. **Cluster bootstrap**: Talos machineconfigs generated by talhelper; Cilium CNI embedded as a Talos inline manifest
4. **GitOps takeover**: A single `helm install argocd` + `kubectl apply root-app.yaml` hands all remaining components to ArgoCD

## Common Commands

All targets require `CLUSTER=<name>` matching a directory under `clusters/`.

```bash
# New cluster — one-time setup
mkdir clusters/talos-01
cp clusters/cluster.env.example      clusters/talos-01/cluster.env
cp clusters/terraform.tfvars.example clusters/talos-01/terraform.tfvars
$EDITOR clusters/talos-01/cluster.env
$EDITOR clusters/talos-01/terraform.tfvars
make CLUSTER=talos-01 gitops-render   # generates clusters/talos-01/gitops/
git add clusters/talos-01/gitops/ && git commit && git push

# Full provisioning
make CLUSTER=talos-01 up              # VMs → Talos → ArgoCD → kubeconfig

# Incremental targets
make CLUSTER=talos-01 tofu-plan       # preview infrastructure changes
make CLUSTER=talos-01 talos-config    # re-render + apply machineconfigs
make CLUSTER=talos-01 argocd-bootstrap
make CLUSTER=talos-01 argo-pwd        # print ArgoCD admin password
make CLUSTER=talos-01 status          # nodes + ArgoCD apps
make CLUSTER=talos-01 gitops-render   # re-render after cluster.env changes
make CLUSTER=talos-01 down            # destroy cluster (MinIO state kept)
make CLUSTER=talos-01 clean           # remove local generated files

# Direct script subcommands (CLUSTER must be exported)
export CLUSTER=talos-01
scripts/bootstrap.sh render      # render Cilium inline + talconfig only
scripts/bootstrap.sh genconfig   # render + talhelper genconfig
scripts/bootstrap.sh apply       # genconfig + apply to nodes
scripts/bootstrap.sh bootstrap   # talosctl bootstrap + kubeconfig
scripts/bootstrap.sh kubeconfig  # fetch kubeconfig only
scripts/bootstrap.sh health      # wait for cluster health
```

## High-Level Architecture

```
Operator Machine (Makefile + clusters/${CLUSTER}/cluster.env)
    │
    ├─→ OpenTofu (tofu/)
    │   • Provisions Talos VMs on Proxmox (bpg/proxmox provider)
    │   • Downloads Talos ISO from Image Factory (schematic.yaml → factory.talos.dev)
    │   • State: MinIO S3 key = ${CLUSTER}/terraform.tfstate
    │   • On `tofu-publish`: uploads clusters/${CLUSTER}/kubeconfig to MinIO
    │
    ├─→ scripts/bootstrap.sh (Talos configuration)
    │   • reads cluster info from OpenTofu outputs / tofu console -var-file
    │   • renders Cilium Helm chart → talos/patches/cilium-inline-manifest.generated.yaml
    │   • renders talconfig.yaml from talos/talconfig.yaml.tpl
    │   • talhelper genconfig → clusters/${CLUSTER}/clusterconfig/ (per-node machineconfigs)
    │   • talosctl apply-config → nodes; talosctl bootstrap → first CP
    │   • talosctl kubeconfig → clusters/${CLUSTER}/kubeconfig
    │
    └─→ scripts/bootstrap-argocd.sh (GitOps takeover)
        • helm install argocd (Cilium is already running via inline manifest)
        • kubectl apply clusters/${CLUSTER}/gitops/projects/platform.yaml
        • kubectl apply clusters/${CLUSTER}/gitops/bootstrap/root-app.yaml
        • ArgoCD syncs clusters/${CLUSTER}/gitops/apps/* (sync-wave ordered)
```

### Why Cilium Is an Inline Manifest

Cilium (CNI) must be running before any pod (including ArgoCD) can start. Instead of a separate `helm install cilium` bootstrap step, Cilium is rendered via `helm template` and embedded in the Talos cluster machineconfig as an `inlineManifest`. Talos applies it at cluster bootstrap. ArgoCD then adopts the running Cilium deployment via `gitops/apps/00-cilium.yaml` on its first sync.

### Per-Cluster Layout

```
clusters/
  <name>/
    cluster.env          # secrets (gitignored) — loaded by lib.sh and Makefile
    terraform.tfvars     # cluster sizing, versions (committed)
    gitops/              # rendered by gitops-render, committed, read by ArgoCD
      bootstrap/root-app.yaml
      projects/platform.yaml
      apps/              # ArgoCD Application manifests (ArgoCD reads this path)
      metallb/           # MetalLB IP pool (cluster-specific)
      argocd/            # ArgoCD Ingress (cluster-specific host)
      cert-manager/      # ClusterIssuer (email from cluster.env)
      doppler/           # DopplerSecret CRs (tokens from Doppler)
    kubeconfig           # gitignored
    talosconfig          # gitignored
    clusterconfig/       # gitignored (generated machineconfigs)

gitops/                  # TEMPLATES — source for gitops-render.sh
  apps/                  # ArgoCD Application templates (with __PLACEHOLDER__)
  bootstrap/root-app.yaml
  projects/platform.yaml
  metallb/, argocd/, cert-manager/, doppler/

talos/                   # Shared Talos templates (all clusters)
  talconfig.yaml.tpl
  patches/
    cluster-common-base.yaml
    controlplane-api-access.yaml
    controlplane-cluster.yaml     (template with ${VARS})
    *.generated.yaml              (per-run, gitignored)

tofu/                    # Shared OpenTofu modules
  modules/talos-node/
  *.tf

bootstrap/               # Helm values for initial ArgoCD install
  argocd-values.yaml     # minimal bootstrap values (ArgoCD self-manages via gitops)
  cilium-values.yaml     # used to render Cilium inline manifest
```

### ArgoCD App-of-Apps Sync Waves

ArgoCD root app watches `clusters/<name>/gitops/apps/` and syncs in wave order:

| Wave | Apps |
|------|------|
| -2 | 00-cilium (adoption of existing) |
| -1 | 05-argocd (self-managed) |
| 0 | 11-metallb-config (namespace PSS privileged + IP pool) |
| 1 | 16-platform-namespaces, 10-metallb, 18-doppler-operator |
| 2 | 17-doppler-secrets, 19-cert-manager, 20-ingress-nginx |
| 4 | 21-argocd-ingress, 22-cert-manager-issuers |
| 5 | 24-external-dns-cloudflare, 25-external-dns-unifi |
| (default) | 30-longhorn |

### Template Placeholder System

`gitops/` contains templates with `__PLACEHOLDER__` markers. `make gitops-render` substitutes them into `clusters/<name>/gitops/`:

| Placeholder | Source |
|---|---|
| `__ARGOCD_GIT_REPO__` | `ARGOCD_GIT_REPO` in cluster.env |
| `__ARGOCD_GIT_REVISION__` | `ARGOCD_GIT_REVISION` |
| `__ARGOCD_INGRESS_HOST__` | `ARGOCD_INGRESS_HOST` |
| `__METALLB_POOL_RANGE__` | `METALLB_POOL_RANGE` |
| `__CLOUDFLARE_DOMAIN__` | `CLOUDFLARE_DOMAIN` |
| `__UNIFI_DOMAIN__` | `UNIFI_DOMAIN` |
| `__ACME_EMAIL__` | `ACME_EMAIL` |
| `__DOPPLER_PROJECT__` | `DOPPLER_PROJECT` |
| `__DOPPLER_CONFIG__` | `DOPPLER_CONFIG` |
| `DOPPLER_SERVICE_TOKEN` | via `make apply-doppler-token` only (not in gitops-render) |
| `__CLUSTER__` | `CLUSTER` (directory name) |
| `path: gitops/<x>` | auto-rewritten to `path: clusters/<name>/gitops/<x>` |

## MinIO Layout

All clusters share the same MinIO instance but use per-cluster prefixes (auto-derived, not configurable):

```
<MINIO_STATE_BUCKET>/
  talos-01/terraform.tfstate
  talos-02/terraform.tfstate

<MINIO_KUBECONFIG_BUCKET>/
  talos-01/kubeconfig
  talos-02/kubeconfig
```

## Configuration Files

### clusters/<name>/cluster.env (gitignored)

From `clusters/cluster.env.example`. Key variables:
- **Proxmox**: `PROXMOX_VE_ENDPOINT`, `PROXMOX_VE_API_TOKEN`
- **MinIO**: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `MINIO_ENDPOINT`, `MINIO_STATE_BUCKET`, `MINIO_KUBECONFIG_BUCKET`
- **ArgoCD**: `ARGOCD_GIT_REPO`, `ARGOCD_GIT_REVISION`, `ARGOCD_INGRESS_HOST`, `ARGOCD_CHART_VERSION`
- **Cilium**: `CILIUM_CHART_VERSION`
- **MetalLB**: `METALLB_POOL_RANGE` (e.g. `192.168.1.60-192.168.1.79`)
- **DNS**: `CLOUDFLARE_DOMAIN`, `UNIFI_DOMAIN`

### clusters/<name>/terraform.tfvars (committed)

From `clusters/terraform.tfvars.example`. Controls cluster sizing:
- `proxmox`: node, datastores, bridge, optional VLAN tag
- `cluster`: name (must match directory name), optional `kubernetes_api_host`, Talos/K8s versions
- `control_plane`: count (odd ≥1), cores, memory, disk
- `worker`: count, sizing, optional `longhorn_disks`
- `minio`: endpoint, state and kubeconfig bucket names (keys are auto-derived)

## Troubleshooting

- **API unreachable `:6443`**: Check first CP DHCP IP via `tofu -chdir=tofu output -json control_plane_nodes -var-file=clusters/<name>/terraform.tfvars`. Override with `cluster.kubernetes_api_host` in tfvars.
- **Cilium pods CrashLoopBackOff**: Verify `kubeProxyReplacement: true` and `cluster.proxy.disabled: true` in `talos/patches/cluster-common-base.yaml`. Check that the `k8sServiceHost` in the inline manifest matches the actual control-plane IP.
- **Longhorn cannot find disks**: Verify `/var/mnt/longhorn-*` inside worker pods; check node label `node.longhorn.io/create-default-disk=config`.
- **gitops-render not run**: `bootstrap-argocd.sh` checks for `clusters/<name>/gitops/bootstrap/root-app.yaml` and fails with a clear message if missing.
- **tofu console fails**: Ensure `CLUSTER` is exported and `clusters/<name>/terraform.tfvars` exists before running bootstrap scripts directly.
